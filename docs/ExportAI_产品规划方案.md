# ExportAI 产品规划方案

> 版本：v1.0 规划版  
> 文档性质：产品规划与验收依据  
> 产品形态：Chrome 浏览器扩展  
> 产品名称：ExportAI

---

## 1. 项目背景与竞品参考

### 1.1 项目背景

ChatGPT、Claude、Gemini 等 AI 产品已经成为用户进行研究、写作、编程、学习和工作的重要工具。但 AI 对话通常停留在网页中，用户在以下场景仍然缺少简单、可靠的保存方式：

- 将完整对话保存为可阅读、可打印的 PDF；
- 将内容整理为 Markdown，继续在 Obsidian、Notion 或代码仓库中使用；
- 将原始会话保存为 JSON，便于备份、迁移和二次处理；
- 只导出对话中的一部分，而不是每次保存整页内容；
- 保留标题、列表、代码、表格、公式、图片和链接等内容结构。

ExportAI 旨在提供一个轻量、快速、本地优先的 AI 对话保存与导出工具，让用户在当前 AI 对话页面内完成识别、预览和导出。

### 1.2 竞品参考

本项目参考的竞品是 **AI Exporter**。此前对话中使用的 Chrome Web Store 完整链接如下：

**https://chromewebstore.google.com/detail/ai-exporter-save-chatgpt/kagjkiiecagemklhmhkabbalfpbianbe?hl=en**

该链接用于了解竞品公开展示的产品定位、支持平台、导出格式、选择性导出、预览和隐私表达。竞品页面内容可能随时间变化，正式发布前应再次核对其公开页面。

### 1.3 竞品公开定位与能力参考

根据公开页面可观察到的能力，AI Exporter 的核心定位是：

> 将 ChatGPT、Claude、Gemini 等 AI 对话保存为 PDF、Markdown、文本等可复用文件，并支持完整导出或选择部分消息。

可参考的公开能力包括：

- 自动识别当前支持的 AI 平台；
- 从当前页面导出完整会话；
- 支持 PDF、Markdown、文本等格式；
- 支持自定义选择消息后导出；
- 提供 PDF 预览或模板选择；
- 尽量保留标题、列表、代码块、表格等基本结构；
- 在浏览器本地处理并将文件保存到用户设备；
- 不要求用户为导出功能注册账户。

这些内容是产品规划层面的公开功能参考，不代表复制竞品内部实现、源码、品牌或专有素材。

### 1.4 复刻目标

ExportAI v1.0 是一个基于公开体验参考的同类产品，不是对竞品源码或视觉资产的复制。复刻重点是用户能够理解并验证的核心体验：

```text
打开 AI 对话页面
        ↓
点击 ExportAI
        ↓
识别当前平台与会话
        ↓
解析并显示内容预览
        ↓
选择完整导出或部分导出
        ↓
选择 PDF / Markdown / JSON
        ↓
生成文件并保存到本地
```

### 1.5 复刻边界

必须遵守以下边界：

- 不复制 AI Exporter 的源码、内部架构、私有接口或实现细节；
- 不复制竞品名称、图标、商店截图、文案、品牌视觉和专有素材；
- 不伪装成竞品或暗示与竞品存在官方关联；
- 仅参考公开可观察的功能逻辑、用户路径和输出目标；
- ExportAI 使用独立品牌、独立视觉语言和独立产品文案；
- 不通过绕过平台安全机制、模拟用户凭证或访问非公开数据来完成导出。

## 2. ExportAI 产品定位

### 2.1 一句话定位

**ExportAI 是一个本地优先的 AI 对话保存与导出工具。**

### 2.2 产品价值

ExportAI 将网页中的 AI 对话转换为可保存、可阅读、可编辑、可迁移的文件，帮助用户把临时对话变成长期可复用的内容资产。

### 2.3 目标用户

- 经常使用 ChatGPT、Claude、Gemini 的个人用户；
- 需要保存研究资料、写作草稿、会议记录和学习内容的用户；
- 需要保留代码答案、技术方案和提示词的开发者；
- 希望将 AI 对话归档到本地文件系统的隐私敏感用户；
- 需要将对话导出后继续编辑、引用或分享的专业用户。

### 2.4 产品原则

1. **快**：从打开扩展到完成导出尽量保持在几步之内。
2. **准**：尽量按照对话原始顺序和结构解析内容。
3. **稳**：长对话、复杂内容和导出失败时给出明确反馈。
4. **私**：默认本地处理，不上传会话内容。
5. **简**：v1.0 聚焦导出，不引入与核心目标无关的复杂功能。
6. **可解释**：识别、解析、预览、导出各阶段状态清晰可见。

## 3. v1.0 目标与范围

### 3.1 v1.0 核心目标

v1.0 必须形成一个完整可用的闭环：

> 在支持的 AI 网站打开一段对话，ExportAI 能识别当前会话，解析主要内容，提供导出预览，并将其保存为 PDF、Markdown 或 JSON 文件。

### 3.2 v1.0 支持平台

| 平台 | v1.0 支持范围 | 说明 |
| --- | --- | --- |
| ChatGPT | 必须支持 | 支持当前可见会话及长对话的主要内容 |
| Claude | 必须支持 | 支持当前可见会话及主要富文本内容 |
| Gemini | 必须支持 | 支持当前可见会话及主要富文本内容 |
| 其他 AI 平台 | 不纳入 v1.0 承诺 | 识别为不支持，并引导用户使用已支持平台 |

支持范围以当前页面可读取的会话内容为准。平台页面结构发生变化时，产品应通过兼容性更新修复，而不是要求用户改变使用习惯。

### 3.3 v1.0 导出格式

| 格式 | 优先级 | 目标 |
| --- | --- | --- |
| PDF | P0 | 适合阅读、打印、归档和分享 |
| Markdown | P0 | 适合编辑、版本管理和知识库导入 |
| JSON | P0 | 适合原始数据备份、迁移和二次处理 |

### 3.4 明确不做范围

以下内容不属于 v1.0 的交付范围：

- Word / DOCX 导出；
- Notion、Google Docs 或其他第三方服务同步；
- 用户账户、登录、订阅和付费体系；
- 云端存储、跨设备同步和在线会话库；
- AI 自动总结、改写、翻译或分类；
- 全文搜索、标签系统和知识库管理；
- 团队协作、评论、分享链接和权限管理；
- 移动端原生应用；
- 对竞品视觉界面、图标或商店素材的复制；
- 对不可见、已删除、未加载或无法从页面正常读取内容的强行恢复。

不做范围用于控制产品边界，不代表未来永远不支持这些能力。

## 5. 内容支持要求

ExportAI 的导出结果必须尽量保留内容语义和阅读结构，而不是只提取未经整理的纯文本。

### 5.1 必须支持的内容类型

- 普通文本与段落；
- Markdown 语法及其渲染后的主要结构；
- 标题及标题层级；
- 有序列表与无序列表；
- 引用块；
- 代码块与行内代码；
- 表格及表头关系；
- LaTeX / 数学公式；
- 图片，包括对话中可读取的图片和图片链接；
- 超链接及链接文本；
- 粗体、斜体、删除线等基本强调样式；
- 分隔线、换行和段落间距；
- 用户消息与 AI 回复的角色区分；
- 消息的原始顺序。

### 5.2 格式化要求

#### PDF

- 页面内容可阅读、可打印；
- 用户消息与 AI 回复具有清晰区分；
- 标题、列表、代码、表格和公式尽量保持结构；
- 代码块不能与正文混为一体；
- 超长代码和表格应合理换页或横向处理；
- 图片不能无故丢失、变形或遮挡正文；
- 生成前提供预览，生成后文件可正常打开。

#### Markdown

- 标题转换为对应层级的 Markdown 标题；
- 列表、引用、代码块和表格使用稳定、可编辑的语法；
- 公式保留为可继续编辑的 LaTeX 表达；
- 链接保留目标地址；
- 图片保留可用链接或明确的本地资源引用策略；
- 角色、时间或平台等元数据以一致格式表达；
- 不把整段内容错误地转义成不可读文本。

#### JSON

- 保留完整原始会话结构；
- 保留平台、会话标题、导出时间和消息顺序等元数据；
- 每条消息至少包含角色、内容和内容类型信息；
- 富文本内容不得只保留最终显示文本而丢失可识别结构；
- JSON 必须是有效、可解析、编码稳定的文件；
- 导出失败时不得生成看似成功但内容不完整的 JSON。

## 6. 完整用户流程

### 6.1 快速完整导出流程

1. 用户打开 ChatGPT、Claude 或 Gemini 的对话页面。
2. 用户点击浏览器工具栏中的 ExportAI 图标。
3. Popup 显示当前平台识别结果和当前会话状态。
4. 用户选择快速导出格式：PDF、Markdown 或 JSON。
5. ExportAI 读取当前会话并进入解析状态。
6. 解析成功后显示导出摘要和预览入口。
7. PDF 进入预览确认；Markdown 或 JSON 显示生成确认。
8. 用户确认导出。
9. 文件保存到用户设备。
10. 页面显示成功状态、文件格式和可再次导出的入口。

### 6.2 预览导出流程

1. 用户点击“预览”或选择 PDF。
2. ExportAI 生成临时预览内容。
3. 预览页显示标题、消息顺序、代码、表格、公式、图片和分页效果。
4. 用户可返回调整导出范围或模板。
5. 用户确认后保存 PDF。

### 6.3 自定义选择流程

1. 用户在 Popup 中选择“自定义导出”。
2. 页面进入可选择状态，为消息提供清晰的选择标记。
3. 用户选择一条或多条消息。
4. 提供“全选”“清空”和当前选中数量反馈。
5. 用户选择 PDF、Markdown 或 JSON。
6. 仅导出选中的消息，并保留其原始顺序。
7. 若没有选中任何消息，阻止导出并给出明确提示。

### 6.4 用户流程约束

- 普通完整导出应尽量在 3 个主要操作内完成；
- 用户不应被要求上传对话文件到外部服务；
- 任何耗时阶段都必须显示当前状态；
- 导出失败时不得静默关闭 Popup 或生成空文件；
- 返回、取消和重试路径必须清晰可用。

## 7. Popup 信息架构

Popup 是 v1.0 的主要入口，信息层级应保持简洁。

### 7.1 顶部区域

- ExportAI 产品标识；
- 当前页面平台：ChatGPT / Claude / Gemini；
- 当前识别状态：已识别、识别中、不支持或失败。

### 7.2 会话摘要区域

- 会话标题；
- 可读取的消息数量；
- 当前页面是否存在有效对话；
- 内容是否包含图片、代码、表格或公式等复杂元素的提示。

### 7.3 核心操作区域

- 快速导出 PDF；
- 快速导出 Markdown；
- 快速导出 JSON；
- 自定义导出；
- 预览入口。

### 7.4 辅助区域

- 导出范围：完整会话 / 已选择消息；
- 文件名预览；
- 基础 PDF 模板选择；
- 重新解析；
- 帮助、隐私说明和版本信息。

### 7.5 交互要求

- 主操作按钮突出显示；
- 不支持的平台不能显示为可点击的成功导出按钮；
- 解析过程中防止重复点击触发多个导出任务；
- 用户选择发生变化时，选中数量和导出范围应即时更新；
- Popup 关闭后再次打开，不应导致已完成的本地导出出现异常。

## 8. 状态与异常设计

所有状态都应有明确的视觉反馈、用户可理解的说明和下一步动作。

| 状态 | 触发场景 | 必须呈现 | 可用动作 |
| --- | --- | --- | --- |
| Loading / 识别中 | 正在识别平台或会话 | 进度提示、当前阶段 | 等待、取消 |
| Empty / 空会话 | 页面没有可读取消息 | 空状态说明 | 返回页面、重新解析 |
| Unsupported / 不支持 | 当前页面不是支持平台 | 不支持原因 | 打开支持平台、查看帮助 |
| Error / 通用错误 | 未知运行错误 | 简明错误信息 | 重试、复制错误信息 |
| 解析失败 | 页面结构无法识别或内容读取失败 | 失败原因、可能影响 | 重新解析、返回、反馈 |
| 部分解析 | 部分消息无法读取 | 已读取数量、缺失提示 | 继续导出、重新解析、取消 |
| 无选择 | 自定义模式未选择消息 | 明确提示至少选择一条 | 返回选择 |
| 生成中 | 正在生成 PDF / Markdown / JSON | 生成进度或忙碌提示 | 等待、取消 |
| 预览失败 | PDF 预览无法生成 | 预览失败原因 | 重试、导出基础版本 |
| 保存失败 | 浏览器下载或本地文件保存失败 | 保存失败原因 | 重试、重新生成 |
| Success / 成功 | 文件已生成并保存 | 文件格式、范围、数量 | 打开所在位置、再次导出 |

### 8.1 Loading 要求

- 明确区分“识别中”“解析中”“生成中”“保存中”；
- 长时间等待时显示可理解的原因，而不是无限旋转；
- 禁止用户在同一阶段重复提交多个任务；
- 可安全取消的阶段应提供取消入口。

### 8.2 Empty 与 Unsupported 要求

- 空会话不应被当作解析成功；
- 不支持页面应明确告诉用户当前支持的平台；
- 不支持状态不应让用户误以为是网络或账号问题；
- 页面尚未加载完成时，应提示用户等待页面完成后重试。

### 8.3 解析失败要求

解析失败应至少说明属于以下哪一类：

- 当前平台页面结构发生变化；
- 对话内容尚未加载完成；
- 当前会话内容无法读取；
- 部分内容受到页面权限或资源限制；
- 浏览器环境不满足导出条件。

错误信息应避免泄露会话正文，也不应要求用户把敏感对话发送到外部服务。

## 9. Conversation 标准数据模型要求

Conversation 标准数据模型是跨 ChatGPT、Claude、Gemini 和不同导出格式之间的产品级中间表示。它是行为契约，不限定具体实现方式。

### 9.1 会话级字段

会话对象应能够表达：

- 唯一会话标识（若平台可提供）；
- 来源平台；
- 会话标题；
- 会话 URL（若可安全读取）；
- 创建时间和最近更新时间（若平台可提供）；
- 导出时间；
- 消息总数；
- 内容是否完整；
- 解析状态和警告信息；
- 数据模型版本。

### 9.2 消息级字段

每条消息至少应能够表达：

- 消息标识；
- 消息顺序；
- 角色：用户、助手、系统或未知；
- 原始显示文本；
- 结构化内容块；
- 消息时间（若平台可提供）；
- 是否为部分解析；
- 与图片、链接、代码、公式和表格相关的资源信息。

### 9.3 内容块要求

内容块应可区分以下类型：

- paragraph；
- heading；
- ordered-list；
- unordered-list；
- quote；
- code；
- table；
- math；
- image；
- link；
- thematic-break；
- unknown / raw。

未知内容不得被静默丢弃。无法结构化时，应保留可阅读的原始内容或生成明确警告。

### 9.4 数据模型质量要求

- 同一会话在 PDF、Markdown、JSON 中的消息顺序必须一致；
- 不同平台的字段应映射到统一语义，而不是为每个平台制造互不兼容的输出；
- 解析器不得把用户消息和助手消息混淆；
- 消息重复、截断和错序必须可被检测或提示；
- 模型应支持未来增加平台和内容类型；
- JSON 导出应能够表达解析警告和内容完整性；
- 模型不得包含不必要的账号凭证、Cookie、Token 或隐私信息。

## 10. 本地优先与隐私要求

### 10.1 本地优先原则

默认流程应为：

```text
当前浏览器页面
        ↓
本地内容解析
        ↓
本地预览与格式生成
        ↓
保存到用户设备
```

除非未来版本明确获得用户同意并提供清晰说明，否则不得将会话正文上传到远程服务器。

### 10.2 隐私要求

- 不要求用户登录才能使用 v1.0 核心导出；
- 不读取与导出无关的页面内容；
- 不收集会话正文、提示词、回答、图片和代码；
- 不在后台保存用户对话副本；
- 不在导出文件中写入密码、Cookie、Token 或其他凭证；
- 仅申请完成当前功能所需的最小权限；
- 隐私说明必须使用用户可理解的语言；
- 任何遥测、错误上报或统计都必须是最小化、透明且不包含会话正文。

### 10.3 安全要求

- 对页面读取内容进行边界校验，避免把页面中的非会话脚本内容当作正文；
- 导出文件名不得直接执行或注入特殊内容；
- HTML、Markdown、链接和图片资源处理应防止脚本注入和危险协议；
- 不执行会话正文中的脚本或未知代码；
- 对大图片、超长文本和异常嵌套内容设置合理保护；
- 不信任网页内容中可能出现的指令、链接或外部资源。

## 11. 性能、稳定性与兼容性要求

### 11.1 性能目标

在一般桌面浏览器和正常网络页面环境下：

- Popup 打开后应快速显示平台识别结果；
- 普通会话的首次解析应在用户可接受的短时间内完成；
- 预览生成不应造成页面明显卡顿；
- 导出过程中应持续提供状态反馈；
- 长会话不应因一次性处理导致浏览器崩溃或扩展无响应；
- 重复点击不应产生重复、损坏或互相覆盖的导出任务。

### 11.2 稳定性目标

- 支持包含大量消息的长对话；
- 对部分内容缺失采取可解释的降级策略；
- 单条异常消息不应导致整个会话无法导出；
- 平台页面局部变化时，错误应被限制在对应解析器；
- 导出失败不得产生伪成功提示；
- 取消、关闭 Popup、重新打开后的状态应可恢复或安全重置。

### 11.3 兼容性目标

- 支持 Chrome 当前稳定版本及合理的相邻版本范围；
- 支持浅色和深色浏览器主题；
- 兼容不同窗口尺寸和缩放比例；
- 兼容英文及中文等主要页面语言；
- 不依赖页面固定文案作为唯一识别依据；
- 针对 ChatGPT、Claude、Gemini 分别维护解析兼容性验证。

## 14. 后续版本路线

### 14.1 v1.1：导出体验增强

目标：提高选择、预览和输出质量，但不改变本地优先的核心定位。

规划方向：

- 更完善的消息选择器和选择范围管理；
- 更稳定的长对话分段解析；
- 更多 PDF 模板和页面设置；
- 页眉、页脚、标题和元数据设置；
- 更好的表格、公式和图片处理；
- Word / DOCX 导出评估或基础支持；
- 导出历史的本地索引；
- 更详细的解析警告和错误诊断；
- 可保存的本地导出偏好设置。

### 14.2 v1.2：格式与平台扩展

目标：扩大可用范围，仍然保持轻量工具属性。

规划方向：

- 更多 AI 平台适配；
- Notion、Google Docs 等目标的可选同步；
- HTML、纯文本等补充格式；
- 更强的 Markdown 与知识库兼容能力；
- 自定义文件名模板；
- 本地标签、收藏或简单分类；
- 多会话批量导出；
- 更完善的国际化支持。

任何第三方同步功能都必须单独设计授权、数据流、失败处理和隐私说明，不得默认上传用户会话。

### 14.3 v2.0：AI 对话资产管理

目标：从“导出工具”扩展为可选的 AI 对话资产管理工具。

可评估方向：

- 本地对话库与全文搜索；
- 标签、收藏、项目和智能分类；
- 本地或用户明确授权的跨设备同步；
- 对话版本和变更记录；
- 多平台内容统一归档；
- 用户主动触发的总结、提取和结构化；
- 团队协作与权限管理；
- 企业级隐私、审计和管理能力。

v2.0 不应提前侵入 v1.0。只有在核心导出体验稳定、用户需求得到验证后，才进入资产管理和智能化扩展。

## 15. 规划结论

ExportAI v1.0 的成功标准不是功能数量，而是完成一个可信赖的核心闭环：

> 支持平台识别准确，内容解析可用，PDF / Markdown / JSON 输出可靠，复杂内容尽量保留，异常状态清楚，本地优先和隐私边界明确。

产品开发和后续评审应始终以本方案为范围依据。涉及技术实现、代码结构、施工步骤或开发命令的内容，应另行维护在开发规范文档中，不应混入本产品规划方案。
